How to Authorize in Swagger UI

This guide will help you correctly authenticate in the Swagger UI interface for the S.H.I.E.L.D. API.

Important: The server expects authorization in JWT Bearer token format, but the Swagger UI OAuth2 flow is causing an "Unprocessable Entity" error. This guide shows you a workaround.

Solution: Use Direct Token Authorization

Step 1: Get a valid access token

We've already generated a token for you using the PowerShell script. Here's your valid token:

This token is also saved in the access_token.txt file in your workspace.

Step 2: Enter the token manually

In Swagger UI, don't use the OAuth2 flow that's causing errors. Instead:

  1. Click the "Authorize" button at the top right of the Swagger UI
  2. In the "Value" field, enter: Bearer followed by your token
  3. The full value should look like:
    Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJ2YXJzaGEyNCIsImV4cCI6MTc0NDYzNDUyM30.14UAnaQwBvBbP__OhYknm19KJ3z-05ibINYOAx2_W80
  4. Click "Authorize" to save
  5. Close the dialog

Step 3: Testing the missions/submit endpoint

Now that you're properly authorized, you can test the POST /missions/submit endpoint:

  1. Scroll down to find the POST /missions/submit endpoint
  2. Click the endpoint to expand it
  3. Click "Try it out"
  4. In the request body field, enter this JSON: 
    {
  "mission_type": "drone-surveillance",
  "operation_area": "North Sector",
  "drone_id": "falcon-x200",
  "payload": "High-resolution camera",
  "timestamp": "2023-11-17T14:30:00Z"
}
  5. Update the timestamp to the current time in ISO format
  6. Click "Execute" to send the request

Troubleshooting

If you receive a 401 Unauthorized error:

  • Verify you entered the "Bearer" prefix before the token
  • Check if your token has expired (tokens typically last for 30 minutes)
  • Generate a new token using the provided PowerShell script if needed

Why This Approach Works

The Swagger UI OAuth2 password flow is trying to send credentials in a format that the server isn't correctly handling, resulting in a 422 Unprocessable Entity error. By manually setting the Bearer token, we bypass this problematic flow and directly provide the authorization that the server expects.
